# 写信弹框：正文优先的紧凑布局

## 目标

写信、回复和转发共用同一弹框，正文应是主要操作区。避免发送账号、收件人、抄送、密送使用多层纵向标签占据大半屏幕，同时不能为了节省空间而隐藏真实收件人或丢失草稿数据。

## 交互约定

- 默认显示三行：发件人、收件人、主题。标签与输入同行，用轻分隔线代替多组大边框；发件账号仍可切换。
- 收件人行右侧提供“抄送”“密送”。点击后增加对应行，空行可以通过向上图标收起。
- 草稿恢复、回复全部等场景已有抄送/密送地址时自动展开。已有地址的行不提供收起按钮，防止忘记隐藏字段仍参与发送；清空后可以收起。折叠状态不写入草稿，不修改 to/cc/bcc 数据。
- 多收件人仍可换行、查看和移除；邮件头超过视口比例上限后在自身区域滚动，避免无限挤压正文。
- 普通新建邮件移除重复的功能说明文字；回复/转发继续显示原有上下文提示。
- 富文本功能全部保留。2026-10-19 起编辑器升级为 Tiptap/ProseMirror，字体/字号固定宽度，常用格式在首行，段落/表格等放在「更多格式」；窄屏分组换行，选区由编辑内核管理。详细能力与兼容边界见 [编辑器增强设计](compose-rich-editor.md)。
- 底部自动保存状态、删除草稿、取消和发送保持原行为；附件区域独立滚动并限制最大占高。

## 布局实现

弹框距离顶部 16px，高度为 `min(860px, 100dvh - 32px)`，宽度沿用 1040px 且受屏幕宽度约束。固定邮件头和发送栏，正文通过 flex/grid 使用剩余高度；正文自行滚动，弹框整体不被长正文撑出屏幕。极矮横屏减少辅助标题及间距，确保可继续编辑并操作发送。

Ant Design Vue Modal 被传送到 body 后，外壳不带当前 Vue 组件的作用域属性，因此外壳高度样式使用仅匹配 `.compose-modal` 的全局选择器，不影响其他弹框。Spin 的实际包装层补齐 flex、高度和 `min-height:0`，避免高度传递中断，使正文只能获得内容固有高度。

输入控件的 `width:100%` 仅限定在邮件头字段，不能覆盖正文工具栏的字体、字号选择器。

## 验收场景

1. 新建邮件默认抄送/密送均不展开，邮件头为三行，正文占主要空间，发送栏位于视口内。
2. 展开和收起空抄送/密送，不影响主题和正文；有地址时保持可见。
3. 以模拟接口验证发送 payload 中 to/cc/bcc、主题和正文仍完整，不向真实 SMTP 发送测试邮件。
4. 打开含抄送/密送的旧草稿，两种地址均恢复并自动显示；回复全部使用相同可见规则。
5. 选中文字后点击加粗、切换字号，格式生效且选区没有因工具栏布局改变而失效。
6. 验证 1280×800 桌面、390×844 窄屏、844×390 横屏；邮件头受限滚动，工具栏按空间分组换行，不产生弹框横向溢出，底部发送栏保持可见。

本次不修改后端接口、数据库结构和邮件文件；部署仍须遵循分级备份及不丢用户数据原则。

## 本地验收记录（2026-10-17）

前端类型检查及生产构建通过，仍有既有共享 UI 大 chunk 提示。本地浏览器使用模拟 API，未向真实 SMTP 发送测试邮件：

- 1280×800 新建邮件：邮件头 119px、工具栏 44px、正文编辑区约 440px，发送栏底部在 784px，位于视口内。
- 含抄送/密送的草稿在 390×844 下：正文约 381px，发送栏底部在 828px；844×390 横屏正文约 80px，发送栏仍可操作。
- 输入 40 个收件人后，邮件头封顶 260px，正文仍约 299px，超长地址区域自行滚动。
- 空抄送可以展开/收起，有值时保持可见；草稿恢复后 cc/bcc 自动显示；模拟发送保留全部地址及主题。
- 选中文字后加粗、切换为 18px 字号均生效；桌面和窄屏截图已检查。上述为本地验收，不等于生产验收。
