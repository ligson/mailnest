# 联系人分组与写信选组

## 功能约定

- 联系人与分组为多对多关系，一个联系人可同时属于多个分组；分组名称在同一用户内唯一。
- 通讯录提供分组新建、编辑名称/备注、成员维护和删除；支持按组筛选联系人、批量加入/移出组。删除分组不删除联系人，删除联系人同时清理成员关系。
- 写信的收件人、抄送、密送分别提供选择分组入口，可一次选择多个组，并预览成员数。
- 确认选择时读取当前成员，展开为普通邮箱地址，按邮箱大小写不敏感去重，保留当前栏原有地址与顺序。不同地址栏不擅自搬移或清空地址，密送不会因分组选取转成收件人。
- 空组明确提示，不插入无效占位地址。选择后可逐个移除；发送与草稿保存现有具体地址，不保存动态组引用，避免组变化悄悄改变草稿收件人。
- 全部查询和成员更新都校验当前用户，不能通过猜分组或联系人 ID 访问其他用户。

## 实现与升级

- 新建 contact_groups、contact_group_members 两张派生业务表，GORM 集中模型/迁移，兼容 SQLite、MySQL、PostgreSQL，不改历史邮件或原联系人字段。
- 成员变更在事务内校验归属并原子替换；分组删除与成员清理在同一事务。
- 后端入口位于 internal/modules/contacts，公共存储仍在 internal/storage；前端业务模块位于 src/modules/contacts，写信入口位于 src/modules/mail/compose。
- 复用现有鉴权、请求客户端和统一 JSON envelope。联系人搜索分页、防抖；按需加载分组和成员，不增加邮件首屏全量通讯录读取。
- 部署另按备份规范进行新增表迁移和回归验收；本次开发不自动发送真实邮件或修改生产数据。
- 本功能涉及新增表，首次生产升级按 L2 备份并验证旧联系人、邮件及附件仍可用，不重建或搬移邮件文件；本轮只完成本地实现与测试，未部署 NAS。

## 使用方式

1. 打开「联系人 → 管理分组」，新建分组并搜索添加成员，也可编辑分组名称、备注和成员。
2. 在联系人列表勾选多人，点击「加入分组」；选定某组筛选后可批量「移出当前分组」，不影响联系人或其他组。
3. 写信时点击收件人、抄送或密送右侧的分组图标，勾选一个或多个分组，查看合并人数后添加到地址栏。添加后仍可逐个增删地址。
4. 确认选组时读取最新成员并形成具体地址快照；此后编辑分组不会改动已打开的邮件或已保存草稿，重新选组才会再次读取成员。

## 性能与边界

- 分组列表分页，搜索防抖并取消旧请求；选组组件首次使用时才加载，不给邮件首屏增加全量成员请求。
- 单次成员变更最多 10000 人，单次展开最多 100 个分组，超出明确提示分批操作而非截断。分组维护使用修订号防止旧表单覆盖别人刚维护的成员。
- 同一地址栏按邮箱去重；不同地址栏保持各自输入，不自动把密送地址挪到收件人。实际发送仍受已有邮件发送校验及邮箱服务商人数限制。
- 手机默认展示窄图标侧栏，展开菜单覆盖内容，不把通讯录挤成窄条；桌面原折叠偏好独立保留。

## 验收重点

- 多组成员重叠、重复选组不产生同栏重复邮箱；昵称优先，地址保持可查看和移除。
- 分组增删改、跨用户隔离、无效/异用户成员整组回滚、联系人删除清理、迁移可重复执行。
- 收件人/抄送/密送分别选组、取消不修改、空组提示、草稿恢复、中文与手机宽度。
