# 再次发送、版本记录与界面优化

## 再次发送

邮件详情的“再发一封”用于重新发送同一封邮件。它复制原邮件的收件人、抄送、密送、主题和正文，普通附件默认全部选中，用户可以在发送前取消附件。该操作使用独立的 `resend` 写信模式，不生成回复引用头，也不改变原邮件。

发送前可以修改地址、主题、正文和附件。草稿自动保存后仍可以从草稿箱继续编辑。原邮件没有保存密送地址时，页面只能沿用系统已有的收件人和抄送数据。

## 版本发布内容

系统管理显示前端和后端运行版本。点击版本号打开发布内容弹窗，展示已经整理到 `CHANGELOG.md` 的版本摘要。版本信息仍来源于当前前端构建和后端运行二进制，发布内容属于前端静态展示，后续发布时同步更新此处和更新日志。

## 附件中心

附件中心首屏请求 `includeTotal=false`，后端直接返回当前页，不执行附件表的 `COUNT(*)`。返回 `totalPending=true` 时前端使用当前页判断是否可以继续翻页。用户进行筛选、刷新或翻页时仍使用同一用户隔离和原有附件查询条件。需要精确总数的调用仍可以省略该参数。

筛选账号和本地文件夹在首屏列表请求之后异步加载，避免元数据请求阻塞附件列表首次显示。

## 联系人分组成员

分组编辑器使用成员表格展示联系人名称和邮箱，支持搜索、分页和勾选。已加载的成员会保留在表格数据中，搜索或翻页不会清空已选状态。保存仍使用原有分组更新接口和修订号校验。
