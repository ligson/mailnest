# 独立邮件阅读窗口

## 使用方式

- 邮件右侧详情操作区增加“新窗口打开”图标，桌面和窄屏都直接可用。
- 链接在新的浏览器窗口或标签页打开，具体由浏览器偏好决定；原邮件列表、筛选和滚动位置不变。
- 独立地址为 `/mail/messages/:messageId`，只包含邮件阅读区域，不显示菜单、账号目录和邮件列表；刷新可以继续阅读，顶部可返回邮箱定位该邮件。
- 复用现有详情、联系人解析、回复/回复全部/转发、规则记录、正文内嵌图片及附件下载功能。加载失败常驻显示错误与“重新加载”，不只短暂弹出通知。

## 正文排版

- 嵌入式预览和独立窗口共用 `mailnest-fe/src/modules/mail/reader/MailBody.vue`。
- 不再为全部元素强制 `max-width: 100%`，不再强制表格单元格任意断字；保留邮件作者的表格和列宽。
- 超出可用宽度的正文按自然宽度展示，在正文容器内部横向滚动，不能挤破页面。窗口宽度改变、图片加载和字体完成加载后重新测量尺寸。
- 纯文本保留换行；HTML 继续使用禁止脚本的 sandbox iframe。新窗口链接使用 `noopener noreferrer`，URL 只包含邮件 ID，不带登录令牌或正文。
- 不保证修复原邮件本身已有的错误 HTML、固定极窄列宽或缺失资源；不修改数据库和原文文件。

## 加载与隔离

- 新路由使用现有路由鉴权，详情与附件仍走现有带用户权限检查的接口，不新增公开邮件接口。
- 独立窗口不请求邮件列表、精确总数和目录；详情请求不等待账号列表，联系人仅解析当前可见地址。账号列表用于后续回复/转发。
- 复用现有详情与写信逻辑，不复制第二套鉴权、附件或编辑器实现。代码按邮件菜单归入 `modules/mail/reader/`。

## 验证

- `npm run test:mail`：正文样式回归，保留表格/图片/引用，避免重新加入全局压缩和任意断字。
- `npm run build`：类型检查与生产构建。
- 独立本地浏览器模拟脚本 `mailnest-fe/scripts/mail-reader-browser.cjs`：验证新窗口链接、宽表格、图片加载、联系人昵称、附件下载、回复全部、刷新与失败重试、独立窗口无多余请求、桌面/手机布局、iframe 禁止脚本和 opener 隔离。所有接口均模拟，不发送真实邮件。
