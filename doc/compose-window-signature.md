# 独立写信窗口与完整签名

## 入口与行为

- 邮件列表“写邮件”右侧提供新窗口图标，打开独立写信路由 `/mail/compose`，沿用当前账号。原弹框写信入口保持不变。
- 写信、回复、回复全部、转发弹框标题栏提供“新窗口写邮件”，先保存草稿，再接续收件人、抄送、密送、主题、正文、本地附件及转发附件。接续成功后原弹框才关闭，失败保留原窗口，并持续显示错误。
- 新页面不加载邮件列表、目录和邮件统计；继续复用同一套表单、编辑器、分组、草稿、发送和权限逻辑。业务入口与窗口专属组件位于 `modules/mail/compose`，暂复用 Dashboard 中的既有写信控制器，避免复制行为；后续控制器拆分需继续保持单一实现。
- 本地附件通过同源 BroadcastChannel 结构化克隆在浏览器内存传递，不重复上传，不写入 URL、localStorage 或日志。链接只包含随机短期通道标识，通道核对用户 ID，窗口隔离 opener。收发双方握手后才交接编辑权；30 秒未完成则保留原窗口，不允许两边同时自动保存。
- 地址栏刷新后不能依靠已经结束的内存通道恢复本地附件；正文等按服务器草稿恢复，本地附件沿用现有“需重新选择”的提示。文件尚未被服务器保存时，关闭/刷新有离开保护。链接不携带认证令牌。

## 签名排版

此前签名 HTML 直接进入普通 ProseMirror schema：布局表格被改成带边框的全宽表格，父级字体、间距和颜色被丢弃。本次将完整签名标记为 `section[data-mailnest-signature]`，作为独立签名节点保留。

- 插入及自动签名统一经过同一入口，保留布局表格、原有行内颜色、字号、边框和间距；签名 iframe 与编辑器默认 CSS 隔离。
- 使用 DOMPurify 清理脚本、事件和活动元素，预览 iframe 禁止脚本并限制资源与导航。发送/草稿序列化输出清理后的普通 HTML，不输出 iframe、不依赖本系统 CSS；纯文本邮件包含签名文本。
- 完整签名不拆为正文段落直接编辑；模板在邮箱账号的“签名模板”中维护，正文可在签名前后继续编辑，也可选中整个签名删除。
- 已经被旧编辑器转换并保存的草稿无法凭空恢复丢失样式，需要删除旧签名并从账号模板重新插入。不批量改写历史邮件、草稿或账号配置。

## 验收边界

- 本轮不修改后端接口、数据库结构或生产邮件文件；不自动部署或发送真实邮件。
- 回归需覆盖有颜色/固定宽度/无边框表格的签名、草稿再打开和发送 HTML、脚本清理、纯文本签名，以及新窗口创建/接续、本地与转发附件、回复上下文、失败保留、桌面及窄屏布局。
