# 联系人批量设置

## 使用方式

在「联系人」表格勾选一位或多位联系人后，工具栏显示「设置公司」「设置分组」。支持跨页勾选；表头全选仅选择当前页，不会隐式选择所有搜索结果。搜索或切换分组筛选时清空选择，避免误改其他范围。

### 批量设置公司

- **仅补全空公司**（默认）：只填充未填写公司信息的联系人，保留已有公司。
- **统一设置公司**：覆盖所选联系人的公司，不改变姓名、昵称、电话、备注等其他字段。
- **清空公司**：必须额外勾选确认，只清空公司字段。

公司名称自动去除首尾空白，最长 120 个字符。变化记录标记为手动维护，避免邮件自动沉淀覆盖用户资料。重复设置相同值不重复计算变化人数，大小写不同视为修改。

### 批量设置分组

- **加入分组**：可同时选择多个分组，保留其他分组，重复加入自动去重。
- **移出分组**：仅删除所选分组中的成员关系，不删除联系人，也不影响其他分组。

选组按需搜索、分页加载，搜索下一组时保留已选分组名称。暂不提供替换全部分组或清空全部关系等高风险操作。

## 交互与失败处理

- 打开弹窗时固定所选联系人快照，不因后续列表变化扩大修改范围。
- 保存期间禁止重复提交、关闭弹窗和修改设置；取消未提交的弹窗不写数据。
- 失败信息保留在弹窗内，保留输入及选择，支持重试；成功后清空勾选并刷新列表和分组计数。
- 成功提示显示实际修改人数或增删的成员关系数，不把没有变化的联系人算作已修改。
- 单次最多 10000 位联系人、100 个分组，联系人与分组组合最多 50000 对；超限明确提示并拒绝，不静默截断。

## 后端与性能

统一接口 `PATCH /api/v1/contacts/batch` 支持公司、分组独立设置，也允许同时提交，两者在一个事务内完成。全部目标必须属于当前用户；不存在或异用户联系人、分组会使整批失败，不跳过部分数据。

沿用既有分组锁顺序（按 ID 排序的分组→按 ID 排序的联系人），先校验全部目标再写入。联系人按每批 200 条执行数据库操作，避免逐人 HTTP 请求及过大的单条 SQL。公司仅更新实际变化行；分组只插入缺失关系或删除明确目标关系。分组修订号同步递增，阻止旧成员编辑表单覆盖新变更。事务成功后按用户失效联系人缓存。

重复执行相同的设置公司、加入分组或移出分组，业务结果一致。若请求网络中断且无法确认是否提交，可重试同一操作；并发操作仍可能产生锁冲突，此时整批回滚并明确报错，不声称永不失败。

## 数据与发布安全

不新增表、不改变数据库结构，不改动邮件文件、附件和账号凭据。兼容现有 SQLite/MySQL GORM 存储；本地回归不访问生产数据。实际发布仍须遵守 `deployment-backup-strategy.md` 的轻量备份、挂载检查和回滚要求。本功能实现不代表已经更新 NAS。
