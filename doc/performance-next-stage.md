# 第二轮性能优化目标与实施记录

## 范围与原则

2026-10-17 开始。改善首次加载、会话列表、宽泛搜索和后台任务竞争，不以延长接口超时、截断搜索结果或长期缓存旧数据代替优化。按菜单模块规范归属新增业务代码，跨菜单性能基础设施独立复用。

## 阶段清单

- [x] 基线：独立数据集、应用缓存冷/热请求、并发与后台写入负载，记录 p50/p95、错误和数据一致性。
- [x] 首屏：静态资源预压缩、哈希资源缓存、UI 按需引入、写信工具栏延迟加载；浏览器回归及生产 HTTP 头验收通过。
- [x] 会话：优化普通会话摘要查询，复杂筛选保留准确性，SQLite/MySQL 回归及幂等迁移测试通过。
- [x] 搜索：Bleve 命中 128 条/批，摘要顺序翻页逐批复核、仅保留当前页前缀；兼容路径 SQL 元数据 64 条/批。兼容签名游标分页，异步精确统计最多一个运行。
- [x] 缓存：按用户和业务域失效，事务提交后生效，回滚不影响；模糊 SQL 保守失效，版本表最多 4096 项。
- [x] 调度：协调同步、导入、索引、统计与历史修复；交互优先但不抢占已运行 SQL，200ms 公平让行，取消排队不占数据库连接。
- [x] 集成：前后端回归、独立 MySQL/SQLite 验证、浏览器验收及安全部署。

## 基线与验收

- 上一版本发布抽样：普通列表 45ms、关键词搜索 86ms、会话列表 2027ms、详情 70ms，属于单次样本，不冒充 p95 或冷启动成绩。
- 发布前主 JS 1,594,028 字节，携带 Accept-Encoding: gzip 仍未返回 Content-Encoding；本轮已补构建预压缩及静态缓存，最终验收记录见下文。
- 严格区分首次进程/索引打开、数据库预热、浏览器缓存、网络下载和渲染。不得清空生产共享 MySQL 缓存。
- 验证中文、单字、数字、邮箱、宽泛及低命中率搜索，多页、同时间邮件、用户隔离、状态变化和并发新增。
- 目标是降低冷读与并发尾延迟；所有数字须附样本量、环境、负载与错误数，未测量不承诺固定倍数。
- NAS 升级按实际 schema/文件风险选择备份级别，仅在本机 Docker 构建；保留数据、配置和回滚镜像，不默认恢复整库覆盖新邮件。

## 可重复验证入口

后端目录运行：

```sh
go test ./...
go test -race ./...
MAILNEST_RUN_PERF=1 MAILNEST_PERF_MESSAGES=50000 go test ./internal/storage -run '^TestPerformanceBaseline$' -count=1 -v
MAILNEST_RUN_PERF=1 go test ./internal/mail -run '^TestMixedImportSyncIndexReads$' -count=1 -v
```

MySQL 通过 `MAILNEST_TEST_MYSQL_DSN` 显式提供一次性独立数据库。功能测试与性能大数据分别使用独立库；同库多包测试使用 `-p 1`，避免两个包同时建表。禁止指向生产库，禁止调用清缓存命令。前端运行 `npm run test:assets`、`npm run test:mail`、`npm run build`。

## 独立负载实测（2026-10-17）

本机 Go 1.26、16 逻辑 CPU；MySQL 为本机 Docker 独立实例、128MiB buffer pool，SQLite 为临时文件。每场景每阶段 80 个样本，并发阶段 8 个读取；数据库/OS 缓存不清除，cache-bypass 仅绕过应用结果缓存，不能当作重启 NAS 后的磁盘冷读。数字为存储层调用，不包含公网 RTT、HTTP 鉴权和浏览器渲染，也不是优化前后的严格 A/B。

| 数据集/场景 | 绕过应用缓存 p95 | 8 并发 p95 | 后台写入并发 p95 |
| --- | --- | --- | --- |
| MySQL 1 万封：列表 | 0.44ms | 2.15ms | 1.83ms |
| MySQL 1 万封：正文稀疏搜索 | 1.26ms | 12.36ms | 2.66ms |
| MySQL 1 万封：宽泛中文搜索 | 12.88ms | 50.78ms | 58.05ms |
| MySQL 1 万封：发件人搜索 | 39.62ms | 131.25ms | 89.07ms |
| MySQL 1 万封：会话列表 | 11.14ms | 56.02ms | 58.98ms |
| SQLite 5 万封：列表 | 0.19ms | 1.99ms | 0.87ms |
| SQLite 5 万封：正文稀疏搜索 | 4.20ms | 22.18ms | 13.85ms |
| SQLite 5 万封：会话列表 | 0.50ms | 1.60ms | 1.62ms |

- 上述阶段错误数均为 0；后台阶段确有 15–25 次更新，不是仅启动空闲 goroutine。合成数据内容、会话分布与生产不同，不能外推固定倍数。
- 真实路径混合验证：临时 SQLite 预置 50 封并等待 active 就绪，再同时启动 EML 导入 50 封、Fake IMAP 收取 50 封、索引重建与异步统计；4 个前台读取、160 样本，最终修正版 p50 0.15ms / p95 5.26ms / max 33.44ms，无错误，最终 150 封且索引 outbox 排空。此前同场景竞态验证也通过（p95 6.70ms，不能与非竞态耗时混用），最终修正版全量 go test -race ./... 通过。只模拟远端传输，不连接真实邮箱。
- 功能回归覆盖中文、单字、数字、邮箱、低命中搜索、跨 128/64 批次、超限完整回退、同时间游标多页、并发新增不重复、用户/筛选绑定和精确统计不受游标影响。
- 摘要顺序游标列表通过候选流式回调逐批准确复核，每批 SQL 只保留当前页所需摘要，不收集完整候选 ID 集合；pending overlay 仍有界保存，以覆盖尚未进入索引的更新。旧精确计数、会话搜索和深随机跳页保留受配置上限保护的 ID 集合兼容路径，超限或索引失败完整回退数据库，不把局部结果当完整结果。流式降低应用内存，并不消除宽泛查询逐批扫描成本。
- UI 按需构建消除单包超过 500KB 提示；主入口约 316KB 原始/113KB gzip，但首屏还会加载共享及路由包，必须按实际网络总量验收，不能只报主入口代表首屏。
- 生产浏览器无缓存加载邮件页记录 19 个静态资源，压缩正文合计 370,215 字节、解压合计 1,147,256 字节；首次未加载写信工具栏。该数不包含 API 响应和 HTTP 头。哈希资源 gzip、Vary 和一年 immutable 缓存，index.html no-cache 已实测，不给鉴权接口设置公共缓存。
- 已知非本轮引入问题：依赖审计仍有 7 项 high；go vet 提示 imap_fetcher.go 的 IPv6 地址拼接格式，后续单独评估修复，不把测试通过等同于所有历史告警清零。

## 生产验收与边界

- 首版流式摘要在生产抽样出现 6–13 秒回退，原因是逐批读取了大量候选正文。修正版增加已验证前缀的数据库时间下界，先排除不可能进入当前页的旧候选，再按 64 条元数据有序复核，不截断潜在匹配。
- 最终修正版公网单次抽样：601 搜索 1318ms，yonyou.com 搜索 734ms；普通列表 46ms，游标续页 45ms，会话 2362ms，详情 224ms。均非 p95、非严格磁盘冷启动，不能外推任意关键字固定耗时；会话仍有秒级波动，后台精确统计仍有扫描成本。
- 真实数据两组查询流式首页与兼容精确路径的 ID 顺序一致，精确总数分别为 570 和 8876；多页、溢出、中文、用户隔离和 pending 更新另由 SQLite/MySQL 回归覆盖。
- 版本页面显示前后端 0.2.1，无横向溢出；健康、现有鉴权、账号、规则、文件夹、列表、搜索、会话、游标、已读详情和附件 206 通过。Bleve ready/active，14372 封就绪，pending/failed 均为 0。
- 执行 L2 在线一致性数据库备份、gzip 完整性与主键集合校验，仅新增派生排序列和两个索引；原配置、持久化挂载、邮件文件不改。原有主键全部保留，期间邮件正常增加至 14372 封；附件 23597、联系人 2458，其他核心表完整。未全量压缩邮件目录。
